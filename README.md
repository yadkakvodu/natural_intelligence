# README.md

# Новостной консультант Альфа-Банка

Интеллектуальный сервис персонализированной новостной аналитики для руководителей крупного бизнеса. Превращает поток внешних новостей и аналитики Альфа-Банка в персонализированные бизнес-инсайты с оценкой рисков, возможностей и экспертной позицией банка.

##  О проекте

**Проблема:** Крупные компании работают с большими объемами операций и сложными цепочками поставок. Руководителям важна не сама новость, а понимание её влияния на конкретный бизнес с учётом отрасли, продуктов банка, ВЭД и других факторов.

**Решение:** AI-сервис, который:
- Анализирует профиль компании (ОКВЭД, продукты, ВЭД, выручка)
- Отбирает значимые события из внешних новостей и аналитики Альфа-Банка
- Формирует персонализированную интерпретацию с рисками и возможностями
- Обеспечивает трассируемость выводов и контроль бюджета LLM

**Целевая аудитория:** Собственники бизнеса, генеральные/финансовые директора, руководители казначейства — ЛПР с доступом к интернет-банку Альфа-Бизнес.

##  Архитектура

### Высокоуровневая схема

```

└─────────────     └────────┬─────────┘     └────────┬────────┘

                      ┌─────────────┐          ┌─────────────┐
                      │ PostgreSQL  │◀────────▶│  LLM API    │
                      │ + pgvector  │          │ (DeepSeek,  │

                                               └─────────────┘
```

### Компоненты

| Компонент | Технология | Роль |
|-----------|-----------|------|
| **Backend Orchestrator** | Java 17+, Spring Boot 3.x | Валидация, Rate Limiting, контроль бюджета LLM (500₽/сутки), трансформация ответов в формат GetAnalyst |
| **AI Core** | Python 3.10+, FastAPI | RAG-поиск (pgvector), rule-based бустинг, генерация через LLM, асинхронная трассировка |
| **База данных** | PostgreSQL 16 + pgvector | Хранение профилей, новостей, эмбеддингов (1024d), истории чата, трейсов агента |
| **LLM Primary** | DeepSeek-V3 | Основная модель для генерации инсайтов и чата (temperature 0.2-0.3) |
| **LLM Fallback** | Qwen2.5-72B-Instruct | Резервная модель при недоступности Primary |
| **Embeddings** | BAAI/bge-m3 | Векторизация текстов для RAG (размерность 1024) |

### Внутренний контракт (Java ↔ Python)

Единый эндпоинт `POST /internal/v1/generate` с полем `request_type`:
- **feed**: Передаёт профиль + параметры поиска → возвращает сырой JSON без пагинации
- **insight**: Передаёт профиль + news_id → возвращает структурированный инсайт
- **chat**: Передаёт готовый массив messages → возвращает ответ ассистента

Сквозная трассировка через заголовок `X-Trace-Id` (UUID).

## ✅ Критерии успеха (как мы их закрываем)

| № | Критерий | Реализация |
|---|----------|-----------|
| 01 | Персонализация по бизнес-контексту | Rule-based бустинг: кредиты → cbr_rate, ВЭД Китай → ved_china |
| 02 | Использование аналитики Альфа-Банка | Поле `bank_position` в инсайте, флаг `is_analytics` |
| 03 | Связь выводов с первоисточниками | Поле `sources` в ответах, `citations` в чате |
| 04 | Устойчивость к новым новостям | RAG с векторным поиском, не зависит от hardcoded сценариев |
| 05 | Полный пользовательский сценарий | Лента → Инсайт → Чат → Источники |
| 06 | Содержательная интерпретация | Структура: what_happened, risks, opportunities, bank_position |
| 07 | Масштабируемость | Модульная архитектура, добавление новых отраслей через конфигурацию |
| 08 | Точка входа в интернет-банке | UI компонент (демо через Swagger/API) |
| 09 | Интерактивность (чат) | POST /chat с сохранением контекста новости |
| 10 | Агентная логика | Планирование → RAG → Генерация → Self-correction |

## 📊 Мониторинг и метрики

### Ключевые метрики

- `news_feed_requests_total` — количество запросов к ленте
- `news_feed_generation_duration_seconds` — время генерации (p50, p95, p99)
- `llm_tokens_consumed_total` — расход токенов (контроль лимита 500₽)
- `avg_relevance_score` — средняя релевантность инсайтов
- `chat_requests_total` — количество вопросов в чате

### Алерты

- Расход токенов > 80% от дневного лимита → уведомление
- p95 latency > 5 сек → алерт (деградация LLM/БД)
- Ошибки 5xx > 5 за 5 минут → алерт DevOps
- Средняя релевантность < 0.4 за час → алерт продуктовой команде

## 🔒 Безопасность и ограничения

### Rate Limiting

| Эндпоинт | Лимит |
|----------|-------|
| `/news-feed` | 30 запросов/мин |
| `/insight` | 20 запросов/мин |
| `/chat` | 20 запросов/мин |
| `/chat-history` | 60 запросов/мин |
| `/sources` | 60 запросов/мин |

### Контроль бюджета LLM

- **Лимит:** 500 рублей в сутки
- **Pre-check:** Прогноз расхода перед вызовом Python (Feed ≈ 2000 ток., Insight ≈ 5000 ток.)
- **Post-update:** Фактический расход из ответа Python
- **Sync:** Синхронизация с БД каждые 5 минут

### Безопасность AI-компонентов

- Валидация `synthetic_u` (regex `^U_[A-Z0-9]+$`)
- Проверка существования клиента/новости ДО вызова Python
- Сквозная трассировка через `X-Trace-Id`
- Изоляция диалогов по `conversation_id`
- В боевой системе: JWT-токен и проверка прав доступа
